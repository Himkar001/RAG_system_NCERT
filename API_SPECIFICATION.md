# API Specification

This document details the RESTful and Streaming API endpoints provided by the Parishiksha (NCERT RAG System) FastAPI backend.

## Base URL
Local Development: `http://localhost:8000`  
Docker Deployment: `http://localhost:8000`

---

## 1. Health Check

Verifies that the backend services, vector database (ChromaDB), and LLM connectivity are operational.

**Endpoint**: `/health`  
**Method**: `GET`  
**Authentication**: None  

### Response (`200 OK`)
```json
{
  "status": "healthy",
  "version": "1.0.0"
}
```

---

## 2. Standard Chat Interaction (Non-Streaming)

Submits a user query and returns the fully formulated response, complete with detected intent, source citations, and optional retrieved images.

**Endpoint**: `/api/chat`  
**Method**: `POST`  
**Content-Type**: `application/json`

### Request Body (`QueryRequest`)
| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `query` | `string` | **Yes** | The user's question. |
| `session_id` | `string` | No (Default: `"default"`) | Unique identifier for the user session to maintain conversational memory. |

**Example Request:**
```json
{
  "query": "Explain Newton's second law of motion.",
  "session_id": "user_12345"
}
```

### Response Body (`QueryResponse`)
| Field | Type | Description |
|-------|------|-------------|
| `query` | `string` | The original query. |
| `answer` | `string` | The Markdown-formatted response generated by the LLM. |
| `sources` | `list[object]` | List of retrieved text chunks used to generate the answer. |
| `intent` | `string` | System-classified intent (e.g., `conceptual`, `numerical`, `equation`, `image`). |
| `image_results` | `list[object]` | List of relevant diagrams/images retrieved from the textbook (only if intent is image-related or highly relevant). |
| `session_id` | `string` | The session ID used for the query. |

**Source Object Structure:**
```json
{
  "index": 1,
  "page": 114,
  "content_type": "paragraph",
  "preview": "The rate of change of momentum of an object is proportional to..."
}
```

**Image Object Structure:**
```json
{
  "path": "/data/processed/rendered_pages/iesc109_page_10.png",
  "score": 0.85,
  "text": "Fig. 9.1: Spring balance showing action and reaction forces."
}
```

## 3. Streaming Chat Interaction (Server-Sent Events)

Submits a user query and streams the LLM response back in real-time. This is the primary endpoint used by the frontend for a responsive ChatGPT-like experience.

**Endpoint**: `/api/chat/stream`  
**Method**: `POST`  
**Content-Type**: `application/json`

### Request Body (`QueryRequest`)
Same as the standard `/api/chat` endpoint.

```json
{
  "query": "Show me a diagram of balanced and unbalanced forces",
  "session_id": "user_12345"
}
```

### Response Stream (SSE - Server-Sent Events)

The stream emits chunked text tokens followed by a final metadata JSON packet containing citations and images.

**Stream Format:**
```text
data: The
data:  forces
data:  are
...
data: [META]{"intent": "image", "sources": [], "image_results": [{"path": "/data/...", "score": 0.9}]}
```

#### Event Handling Logic
1. Clients should append standard `data: ` strings to their response buffer.
2. If a chunk begins with `data: [META]`, clients must parse the trailing JSON string to extract `intent`, `sources`, and `image_results`.
3. The stream terminates when the connection is closed by the server.

---

## Error Handling

All endpoints follow standard HTTP error codes:

* **`400 Bad Request`**: Malformed request payload.
* **`429 Too Many Requests`**: Rate limits exceeded (specifically Gemini API free tier limits). The backend utilizes exponential backoff, but sustained loads may still trigger this.
* **`500 Internal Server Error`**: General backend failure. Responses include detail on the failure point.

**Error Response Body:**
```json
{
  "detail": "Error message describing the failure."
}
```
